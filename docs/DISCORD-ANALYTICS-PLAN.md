# Discord 通知與網站分析規劃（草案）

狀態：架構與驗收規格；尚未建立 Edge Function、分析資料表、Discord Webhook 或定時工作。不可視為已啟用功能。

## 目標

將 Discord 作為營運提醒中心，網站後台仍是資料來源與處理工作的位置。第一階段採免費優先、低流量成本、可搬移的設計；不新增付費資源、不連接正式資料庫、不發布正式網站，直到擁有人明確批准。

## 事件分級與通知節流

| 事件 | Discord 行為 | 原因 |
|---|---|---|
| 每日瀏覽量、訪客估算、熱門商品、搜尋無結果 | 每日摘要一次 | 避免洗版 |
| 加入／移除詢價清單、商品詳情瀏覽 | 累計統計，放入每日摘要 | 加入清單目前是訪客本機行為，不是訂單；不應每次都即時通知 |
| 正式送出詢問／管理員建立待處理工作 | 即時通知 | 這才是可採取行動的營運事件；需先實作後端詢問紀錄 |
| 低庫存、供貨異常、價格來源異常 | 合併重複事件後通知；恢復時補一則 | 避免同一異常反覆提醒 |
| 排程／資料同步／備份失敗 | 立即通知，包含任務與時間，不包含機密 | 屬於營運風險 |
| 商品新增、價格或庫存異動 | 可設定即時或每日摘要 | 由管理員設定，不預設大量播報 |

## 架構決策

1. 瀏覽器只送事件到受控後端端點，不得將 Discord Webhook、服務角色金鑰或其他秘密寫進 index.html、admin.html、公開 Git 或瀏覽器設定。
2. 後端先驗證事件白名單、欄位型別、長度、請求頻率與大小，再寫入分析紀錄；不接受客戶任意指定 Discord 訊息內容。
3. Discord Webhook 只由伺服器端讀取，發送失敗要有重試上限、去重與錯誤紀錄，不能因通知失敗而重複建立訂單或庫存交易。
4. 網站事件與通知傳送分離：事件先落資料，再由定時摘要／通知工作處理；Discord 暫時故障不應遺失原始營運紀錄。
5. 所有時間以 UTC 儲存，日報以 Asia/Taipei 統計；清楚區分瀏覽次數、估算訪客數、商品詳情瀏覽、加入清單與已送出的詢問，不把它們統稱為訂單。
6. 第一階段只記錄必要彙總事件。不得記錄完整 IP、精確位置、客戶姓名／聯絡方式、整份購物車、付款資料、私有成本或供應商資訊。不要使用裝置指紋；匿名 session ID 應隨機產生並設期限。
7. 設定保留期限、資料刪除流程、濫用／機器流量過濾與通知頻率上限；未確認隱私告知與必要性前，不收集可識別個人的分析資料。

## 建議資料事件

- page_view：頁面類型與時間；不保存完整 URL 查詢字串。
- product_view：公開商品 ID／SKU 與時間。
- search：是否有結果；預設只彙總搜尋詞，避免把可能的個人資料寫入日誌。
- cart_add / cart_remove：公開商品 ID、數量區間或次數，不含客戶識別資料；目前本機購物車事件不能跨裝置統計，必須成功送達後端才納入全站報表。
- inquiry_submitted：僅在真正建立後端詢問紀錄時產生，使用詢問單 ID；不可把「複製詢價文字」當成已送出詢問。
- admin_task_created / admin_task_resolved：管理端待處理事項及狀態變更。
- system_alert：經白名單的異常代碼與相關資源 ID；不可直接放入秘密或個資。

## 報表定義

每日摘要至少顯示：瀏覽次數、估算訪客數（若未能可靠去重則標示「未提供」）、商品詳情瀏覽排行、搜尋無結果次數、加入／移除詢價清單次數、真正建立的詢問單數、未處理工作數、低庫存／供貨異常與系統任務狀態。每個數字都要標註統計期間及定義。

不把瀏覽量直接當成真人數，不把加入清單當成購買意願確定，不把複製文字當成已送出詢問，也不以分析事件直接改庫存、建立訂單或觸發付款。

## 實作順序

1. 定義事件契約、資料保留、速率限制與通知等級（本文件）。
2. 先在開發分支建立可測試的事件接收端與資料表草稿；預設關閉，不含真實 Webhook。
3. 加入管理員可設定的 Discord 通知端點與秘密設定說明；不得把秘密提交到 Git。
4. 在 staging 使用虛構事件測試驗證、限流、去重、失敗重試與權限。
5. 接入前台頁面／商品／詢價清單事件，並清楚顯示「本機事件未送達」或關閉追蹤的狀態。
6. 建立台灣時區每日摘要排程、通知去重與失敗告警。
7. 驗證刪除／保留政策、行動版管理流程、Discord 頻道權限及不洩漏私密欄位。
8. 只有在完整驗收及明確批准後才連接正式資料或發布。

## 上線驗收清單

- [ ] 前端原始碼與網路請求不含 Discord Webhook 或服務角色金鑰。
- [ ] 未授權或格式錯誤事件會被拒絕；有速率限制及大小限制。
- [ ] Discord 不可用時，事件資料不丟失且不重複執行業務動作。
- [ ] 每日摘要只在設定時段送出一次，時區跨日測試通過。
- [ ] 加入清單、複製詢價文字、正式建立詢問單三者分開計數。
- [ ] 通知與報表不包含客戶聯絡資料、私人價格／成本、供應商來源或完整購物車。
- [ ] 具備事件保留／刪除與通知停用方式。
- [ ] staging 測試通過；尚未獲批准前不連正式資料庫、不部署正式網站。
