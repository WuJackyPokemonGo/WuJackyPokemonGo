# 分析接收器：staging 驗收與啟用門檻（草案）

狀態：測試規格，尚未部署。這份文件不是啟用授權。

## 啟用前不可省略的條件

- [ ] 使用隔離的 staging 專案與非正式測試資料。
- [ ] 確認資料表 migration 已在 staging 套用，RLS、授權與重複鍵行為已實測。
- [ ] 加入可靠的持久化速率限制或受信任平台層的限流；不能依賴單一 Edge Function 執行個體的記憶體計數。
- [ ] 不可直接信任任意 `X-Forwarded-For`／類似請求標頭來識別用戶；只有確認由部署平台覆寫且無法由客戶端偽造的來源資訊，才可作為限流輸入。
- [ ] 確認資料保留期限、刪除排程、故障告警及成本／配額限制。
- [ ] Webhook 與 service-role key 只存在伺服器秘密設定；測試日誌不得輸出秘密或請求內容。
- [ ] 在 staging 完成下列案例並留存結果；完成後仍須由專案擁有人決定是否啟用。

## 請求與輸入驗收

| 案例 | 預期結果 |
|---|---|
| 未設定 `ANALYTICS_INGEST_ENABLED=true` | 回傳 503，不能寫入 |
| 非 POST 方法 | 回傳 405 |
| Origin 不在 allowlist | 拒絕，不寫入 |
| 缺少／格式錯誤的 JSON | 回傳 400，不寫入 |
| 請求大於 4096 bytes（有或沒有 Content-Length） | 回傳 413，不寫入 |
| 未知事件種類、錯誤 UUID、負數／過大結果數 | 回傳 400，不寫入 |
| 額外傳入原始搜尋字、購物車、聯絡資料、URL、IP 或任意 metadata | 不儲存任何額外欄位 |
| 同一 event_key 重送 | 不新增第二筆；回覆重複接受結果 |
| 資料庫暫時不可用 | 回傳一般化錯誤，不洩漏連線／資料細節 |
| 超出限流門檻 | 回傳 429 或平台定義的限流結果；不寫入事件 |

## 隱私、聚合與清理

- 每日報表只回傳彙總數字與必要的商品識別碼；不讀取原始 session token、IP、完整 URL 或搜尋詞。
- 事件的日期分組使用 `Asia/Taipei`；需測試午夜跨日與夏令時間／時區設定不一致的邊界（台灣目前不採夏令時間，但儲存時間仍使用 UTC）。
- 保留期限由正式設定決定；清理工作必須有測試、可觀測結果與失敗告警，不能只寫在文件裡。
- 確認日報不會把本機加入詢價清單或複製文字誤認為已送出詢問／訂單。

## 部署後驗收

- [ ] 用匿名瀏覽器確認無法直接讀取或寫入事件資料表。
- [ ] 驗證合法 Origin、非合法 Origin 與非瀏覽器請求的處理方式；CORS 不是身份驗證。
- [ ] 確認服務角色金鑰未出現在前端 bundle、Git、回應本文、錯誤日誌或瀏覽器網路紀錄。
- [ ] 驗證限流在多個執行個體／併發請求下仍有效。
- [ ] 驗證資料刪除、備份範圍與還原行為。
- [ ] 取得擁有人明確批准後，才可設定公開環境變數或部署公開端點。

## 已知限制

目前接收器是程式草案；沒有實際資料庫、限流、清理排程、Discord Webhook 或部署。CI 的型別檢查不是 staging 驗收，也不代表可以對外啟用。
