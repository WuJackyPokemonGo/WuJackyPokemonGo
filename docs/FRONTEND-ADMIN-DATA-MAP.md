# 前後台共用資料映射與圖片規則（草案）

狀態：設計文件，尚未建立共用執行程式、雲端同步或 Storage。前台與後台原型仍是獨立資料集；不可直接把目前示範資料當正式庫存匯入。

## 1. 穩定識別碼策略

- 資料庫 `products.id` 使用 UUID，作為內部永久主鍵。
- `sku` 是人可讀、不可重複且建立後不應因改名而變動的商品代碼；例如未來可採 `WJ-000001` 格式，但正式規則仍待確認。
- 前台／後台原型的 `id` 只在各自本機資料集內有效，不能直接假設等於資料庫 UUID 或 SKU。
- 雲端轉換層必須以 SKU 尋找既有商品；第一次導入時建立 SKU→UUID 對照，並保存導入批次與結果。遇到重複 SKU、同一 SKU 對到多個 UUID 或未知 ID，應停止該批次並要求人工處理。
- 禁止用商品名稱、英文別名或圖鑑編號作唯一鍵；同名商品、不同活動背景或不同版本可能是不同商品。

## 2. 欄位標準化建議

| 共用概念 | 正式欄位 | 前台原型來源 | 後台原型來源 | 轉換規則 |
|---|---|---|---|---|
| 永久主鍵 | `id` UUID | `id`（本機） | `id`（本機） | 不直接覆用；以 SKU 對照資料庫 UUID |
| 商品代碼 | `sku` | 尚未獨立欄位 | 尚未獨立欄位 | 新增必填穩定代碼後才能正式同步 |
| 中文名稱 | `name_zh` | `name` | `name` | trim 後保留原始文字 |
| 英文名稱 | `name_en` | 目前部分存在 `aliases` | `aliases` | 不可自動把第一個 alias 當英文名；需人工或明確規則映射 |
| 搜尋別名 | `aliases[]` | `aliases` | `aliases` | 去除空白、保留不同語言別名；不以別名作鍵 |
| 圖鑑編號 | `pokedex_number` | `dex` 字串 | `code` 字串 | 只接受已驗證整數；無法解析的代碼另存備註，不可默默轉成 0 |
| 公開標籤 | 分類關聯表 | `tags[]` | `tags[]` | 先將名稱映射至穩定 category ID；刪除使用中標籤需先處理關聯 |
| 公開價格 | `public_price_twd` | `price` | `price` | 詢價時使用 null + `price_is_inquiry=true`；不能把空字串或 0 當詢價 |
| 庫存餘額 | `inventory_balances` | `stock` 僅示範 | `stock` 本機值 | 不經商品匯入覆寫；以盤點／採購／銷售交易產生 movement |
| 低庫存門檻 | `low_stock_threshold` | 目前前台預設 | `threshold` | 以管理端設定為準；公開端只取得粗略狀態 |
| 公開說明 | `description_public` | `description` | `desc` | 只同步公開文字，內部備註需獨立欄位 |
| 公開狀態 | `publication_status` | 原型顯示資料 | 後台發佈狀態 | 草稿／已發佈／封存與庫存狀態分離 |
| 供貨狀態 | `supply_status` | 原型狀態 | 庫存及門檻推算 | 正式版由可信伺服器規則計算或經驗證的管理操作更新 |

## 3. 圖片資料契約

- 每張圖片是獨立的 `product_images` 記錄，使用資料庫 UUID、`product_id`、`storage_path`、`alt_text`、`sort_order`。
- 商品圖片順序由 `sort_order` 決定；排序需穩定，不能依檔名或上傳時間猜測。
- 前台只能取得已發佈商品、已核准圖片的公開 URL 或受控圖片端點；不能公開整個私有 Storage bucket。
- 圖片上傳前驗證 MIME 類型、檔案大小與解碼結果；拒絕偽裝副檔名、空檔案及不支援格式。產生縮圖並保留原圖備份，前台採延遲載入。
- 刪除商品圖片前確認商品仍有封面；封面替換與排序需可預覽。刪除 Storage 物件應記錄操作者並避免破壞歷史訂單需要的快照。
- 圖片 URL 不應作永久主鍵；搬移 Storage 時保留資料庫圖片 ID，更新 path 並驗證連結。
- `image_rights_note` 是內部授權／來源備註，不等於已取得授權；不得將其公開。

## 4. 公開資料轉換白名單

公開 DTO 僅可包含必要欄位：公開商品 ID 或 SKU、名稱、別名、公開圖鑑編號、公開說明、核准圖片、公開標籤、公開售價／詢價旗標、粗略供貨標籤、公開排序與必要日期。

以下欄位永遠不應進入公開 DTO：精確庫存、單位成本、供應商與來源網址、私人備註、訂單、客戶聯絡資料、收付款、退款、平台費、利潤、管理員 ID、稽核前後值及私有設定。不能先傳到瀏覽器再隱藏。

## 5. 同步及錯誤處理

1. 先在 staging 以複製資料演練，不用真實客戶或付款資料。
2. 每次同步產生 batch ID、來源版本、時間、操作者、讀取／新增／更新／略過／錯誤筆數。
3. 先做 schema 驗證與差異預覽，再由管理員確認寫入。
4. 商品基本資料同步與庫存交易分離；商品更新不可意外重設庫存。
5. 同步失敗需提供可理解的逐筆錯誤，並回滾整批或執行已設計的補償流程；不可悄悄略過錯誤。
6. 重新讀取資料驗證圖片、標籤、公開價格、發佈狀態及 SKU 關聯。
7. 在未完成權限、並行、備份還原與匿名資料暴露測試前，不得連接正式前台。
