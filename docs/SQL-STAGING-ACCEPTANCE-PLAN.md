# SQL 草稿整合與 staging 驗收清單

狀態：規格與審查清單；未連接資料庫、未執行 migration、未建立真實資料。

## 目前不可視為已完成的事項

- 初始 schema、安全政策、手動庫存調整與分析事件 migration 都是草稿；不能因 CI 靜態測試通過就套用。
- 目前只有手動庫存調整函式；採購到貨、銷售扣庫存、取消回庫、退款及訂單狀態轉換仍沒有完整交易函式。
- 手動庫存調整草稿已加入 movement 唯一冪等鍵與前後數量快照；其他訂單／採購／銷售／退款 movement 尚未形成完整的資料庫冪等鍵關聯。靜態檢查不等於並行資料庫測試。
- purchase_batches 目前代表採購批次資料，但尚無「已驗收／已入庫」狀態及冪等收貨鍵；不可直接把建立採購批次當成已到貨或增加庫存。
- 公開商品 view 尚未授權給 anon，管理員初始化流程、Storage 權限、真實 view/RLS 語義及 API 權限仍需在隔離 staging 驗證。
- 分析接收器未部署，沒有持久化跨執行個體限流及保留期限清理工作；保持關閉。

## 手動庫存調整驗收

- [ ] 未登入、一般帳號、非管理員均被拒絕，且任何資料列都不變。
- [ ] 不存在或已封存商品被拒絕。
- [ ] 零調整、空白理由、非有效參數及會造成負庫存的調整被拒絕。
- [ ] 成功時，餘額、movement、audit log 同時寫入。
- [ ] 人為讓 movement 或 audit 寫入失敗，確認整筆交易回滾。
- [ ] 兩個並行調整同一商品時，結果與 movement 加總一致，絕不出現負庫存。
- [ ] 同一 idempotency key、相同操作者／商品／增減量重送時，回傳原始結果且只產生一筆 movement／audit。
- [ ] 同一 key 改用不同操作者、商品或增減量時必須拒絕。
- [ ] 兩個同 key 的併發請求中，確認最多一筆交易提交；若另一請求遇唯一鍵衝突，客戶端可安全重試並取回已提交結果。
- [ ] 不同 key 的並行調整仍須驗證 row lock、movement 加總與餘額一致。

## 訂單、採購與分析的上線阻擋項目

- [ ] 採購到貨函式同一交易寫入採購驗收、庫存餘額、movement、成本／批次關聯與 audit log。
- [ ] 銷售函式同一交易驗證合法訂單狀態、庫存足夠、歷史成本快照、唯一 sale movement 及 audit log。
- [ ] 取消／退款與實物回庫分離；只有核准且實物可再售時才增加庫存。
- [ ] 每種會改變庫存或現金帳的操作都有資料庫層冪等鍵／唯一約束；並行重送測試不重複入庫、扣庫存或記帳。
- [ ] 匿名與一般帳號不能讀寫成本、供應商、客戶聯絡資料、訂單、財務、庫存餘額或稽核紀錄。
- [ ] 公開商品 DTO 只包含核准欄位；不得回傳精確庫存、成本、供應商或私密價格。
- [ ] 分析端點先完成持久化限流、保留／刪除工作、資料庫失敗測試和隱私驗收，才可由擁有人明確批准啟用。
- [ ] 完成 staging 備份與實際還原演練；記錄結果與剩餘風險。

## 退出條件

任何權限、交易回滾、冪等、庫存對帳或備份還原測試失敗，均不得進入正式環境。所有 migration 與公開端點維持未套用／未啟用，直到審查及明確批准完成。
