# Wu Jacky 自助下單：待審版本

此分支未合併、未發布，SQL 與 Edge Function 均未套用。正式站仍使用既有詢價流程。

## 已準備的流程

1. 既有詢價清單可轉往下單；公開且已定價、有足夠可用庫存的商品才接受下單。
2. 買家留下稱呼、聯絡方式及可選備註，同意目前交易說明版本。
3. 伺服器重新確認售價與庫存，在同一交易建立既有 orders/order_items 訂單並保留庫存。
4. 訂單成功後才提供經確認的銀行資料、付款期限及私人查詢碼。銀行與條款版本保留訂單快照。
5. 買家回報實際匯款金額、台灣時間及末五碼；此動作只回報，**不認列收款**。
6. 管理員使用既有收退款功能核對並登錄實際收款，確認商品成本，按「標記待人工交付」。
7. 管理員交貨後使用既有「完成交付並扣庫存」，沿用原有庫存、成本與財務明細。
8. 查詢碼可查狀態；未付款且未回報匯款的訂單可由買家取消。回報或收款後由管理員聯絡處理取消／退款。

## 要由擁有人審定的內容

| 項目 | 待審設定 |
|---|---|
| 收款銀行、代碼、帳號、戶名 | 尚未提供；程式留空，不自行代填 |
| 未付款保留時間 | 預設草案 30 分鐘，可調 10–1440 分鐘 |
| 回報後等待核款的保留時間 | 預設草案 24 小時，可調 1–72 小時 |
| 單筆件數上限 | 預設草案 20 件，可調 1–99 件 |
| 交易說明 | 中英文草案見後台設定，待確認取消／退款與交付約定 |
| 聯絡資料 | 稱呼＋管道＋ID/網址/Email 必填，備註選填 |
| 防機器人驗證 | Turnstile Site Key、Secret、正式 hostname 與允許來源尚未設定 |

「預設草案」不是擁有人已確認的規則。正式開關預設關閉，銀行資料不完整時不能開啟。

## 審查預覽

執行 `python -m http.server 8000` 後，開啟 `http://localhost:8000/checkout-review.html`。
此頁使用模擬商品、展示銀行字樣，不讀寫正式資料庫，也不呼叫驗證服務。可試下單、保存查詢碼、匯款回報、取消未付款訂單、中英切換與手機版。

`checkout.html` 為實際接線頁，未部署服務前會停用下單。現有 index.html 的詢價功能保留；後端開關 enabled=true 才出現自助下單入口。

## 資料與保留

訂單沿用 orders/order_items；保留狀態、雜湊查詢密鑰、銀行快照、匯款回報放在 app_settings 的 checkout_order:<order UUID>。
這些資料已由原有完整備份及還原覆蓋，不更改既有備份版本。app_settings 的 rate 記錄是短期計數，兩分鐘後可清除。
查詢密鑰使用 32 隨機位元組，資料庫只存 SHA-256。買家瀏覽器只長期保存最後查詢碼；待確認下單資料保存在同一分頁 sessionStorage，伺服器不提供訂單號碼猜測查詢。密鑰不放 URL。
收款前的逾期訂單動態釋放庫存，查詢顯示逾期；不刪除歷史訂單。已登錄任何實際收款的訂單繼續保留，需人工處理，不因逾期釋放。
買家回報後延長至設定時限，仍須人工核款；超時未核款會釋放，介面顯示逾期並要求先聯絡。若之後核款，資料庫重新檢查庫存，衝突時阻擋操作，須由管理員聯絡處理。

## 部署步驟（僅審核通過後執行）

1. 取得完整備份及記錄 main SHA，重新比對正式 schema；不得重跑舊 production SQL。
2. 在獨立測試專案套用 `supabase/review/self-checkout.sql`，跑 SQL 驗收及兩個真實瀏覽器競爭最後庫存測試；確認 Supabase advisors 無新增暴露。
3. 審核通過才在正式專案套用同檔（一次），預設 enabled=false。
4. 設定 Edge secrets：`CHECKOUT_ALLOWED_ORIGINS=https://wujackypokemongo.github.io`、`CHECKOUT_TURNSTILE_HOSTNAME=wujackypokemongo.github.io`、`CHECKOUT_TURNSTILE_SECRET`。Secret 不放 GitHub 或前端。Supabase URL/service-role key 使用函式伺服器環境。
5. 部署 `self-checkout` Edge Function，JWT gateway 設為 `verify_jwt=false`（例如 CLI `functions deploy self-checkout --no-verify-jwt`，執行前核對當前 CLI help）。函式本身用 CAPTCHA＋來源白名單＋資料庫限流；資料庫 RPC 僅 service_role 可呼叫，不能直接繞過 CAPTCHA。
6. 合併此分支與建置輸出，確認 GitHub Pages 發布完成；開關仍關閉。
7. 後台填入擁有人確認銀行、條款與公開 Site Key，核對設定後開啟。先以實際瀏覽器驗證付款期限、庫存、匯款回報與人工核款／交付；不使用假的收款登錄。

## 關閉與回復

後台關閉 enabled 會停止新單，但原訂單仍可查詢、回報與管理。不要移除 SQL／欄位或刪除 app_settings 的訂單資料；開關關閉不取消既有保留。需要回復前端時以新提交還原，不 force-push main。不可直接移除保留檢查，否則可能售出已保留庫存。
