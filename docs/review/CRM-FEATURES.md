# Threads 客人特徵與經營篩選：第一段（審核分支）

分支：`feature/crm-features-phase1`。**尚未套用到正式站。**正式站要等驗收通過、老闆同意後才套用。

## 前提
- 正式站目前有 **0 筆網站訂單**。過去的成交都在 Threads 私訊裡完成。
- 「熟客」「成交額」由「已接受的歷史成交」加上「已完成的網站訂單」計算。
- 網站訂單用 `orders.customer_alias` 等於客人名單名稱來對應。
- 歷史成交另存在 `crm_deals`，不寫進 `orders`，以免動到庫存、營收和訂單流程。

## 第一段做了什麼

| 功能 | 規則 |
|---|---|
| 案件（每段詢價或交易各自一個狀態） | 狀態有：我欠回覆、待核款、待交付、待付款、等貨、已報價待回覆、報價後客人未回、棄單、已成交、已結束 |
| 歷史成交建議 | 一次付款加交付算 1 筆，同一筆買多隻仍算 1 筆。要老闆按「接受」才計入，接受時必須有金額，退款不能超過金額 |
| 熟客 | 至少 2 筆計入的成交。全額退款不算；部分退款扣除後若還有金額，仍算 1 筆 |
| 高單價成交 | 單筆成交扣除退款後達到門檻，預設 NT$1,000，可調 |
| 累計成交額 | 計入成交的金額加總，可依金額排序 |
| 回購客久未成交 | 熟客，且距離最近一次成交達到天數，預設 90 天，可調 |
| 有詢價、尚無成交紀錄 | 有詢價，但沒有任何計入的成交 |
| 等貨 | 品項、聯絡管道、下次追蹤日，狀態分待通知、已通知、已結束。可手動新增 |
| 商品搜尋 | 搜尋範圍包括詢價品項、案件品項、成交品項、等貨品項、商品名稱、敘述摘要 |
| 手機卡片 | 顯示暱稱、聯絡管道、成交次數與累計、成交待確認筆數、等貨或關注的商品、下一步，以及另外還有幾件進行中 |
| 篩選 | 首頁放：熟客、高單價成交、等貨、我欠回覆、待核款、成交待確認、商品搜尋。「更多篩選」裡放：回購客久未成交、無成交紀錄、有棄單、案件狀態、舊標籤、排序、門檻設定 |

## 聊天怎麼判斷（全部只是建議）
- **交付**：店主訊息裡有「密碼」。
- **付款**：店主給匯款資訊後 3 天內，客人回「已匯／轉了」或傳圖片。
  - 這類只會標成「待核款」，不會自動變成成交。
- **案件怎麼分段**：
  - 交付後，客人再傳訊息就開新的一段。
  - 隔 14 天以上，而且上一則是店主，也開新的一段。
  - 已付款還沒交付時，客人改問別的商品，也另開一段。
  - 分批交付：3 天內、沒有新的付款，就併回原本那筆。
- **金額優先順序**：
  1. 客人付款訊息裡寫的金額。
  2. 客人出價、店主同意的金額。
  3. 店主付款前最後一次報價。
     - 報「一隻 N」而且買多隻，就乘以隻數。
     - 報「共、＝、一套」就當成總價。
  - 日期、天數、銀行代碼、8591 都會排除。
- **案件狀態**（由上往下，第一個符合的就是）：
  1. 已交付：已成交。
  2. 已付款：待核款。
  3. 客人最後在問價、問庫存或說要買：我欠回覆。
  4. 店主說有貨通知或已登記：等貨。
  5. 已給匯款資訊：7 天內是待付款，超過 7 天是棄單。
  6. 店主報了價、客人沒回：7 天內是已報價待回覆，超過 7 天是報價後客人未回（不算棄單）。
- **重新匯入**：
  - 不會產生重複，以 source_key 判斷是不是同一筆。
  - 人工改過的案件狀態會保留，新的系統判斷另外記在 `suggested_status`。
  - 已接受或已略過的成交不會被更動。
  - 等貨只會新增，不會覆蓋。
- **範圍**：第一輪只替 A 層（疑似付款或熟客候選，119 位）產生建議。

## 第二輪（2026-11-12）：補齊 GPT 規格的其餘功能

### 新增功能
| 功能 | 做法 |
|---|---|
| 高預算意向 | 客人明確出價（「N收」「N可以嗎」），或在店主報價後兩則內回「收／要／好」，才標記。門檻和高單價共用，預設 NT$1,000，可調。每筆記錄金額、品項、日期，以及依據原句 |
| 常問商品 | 同一品項出現在至少 2 筆不同詢價：以不同案件計，沒有案件時以不同日期計；同一串對話重複問只算 1 筆。暱稱待確認或目錄對不到的品項，標示「待確認」 |
| 偏好品類 | 商品表沒有分類欄位，所以從商品名稱和詢價線索**推斷**，分成地點／特殊背景（含「色背」）、異色、服裝皮卡丘、極巨。可以選篩「買過」（只算已接受的成交）或「問過」 |
| 詢價尚無成交紀錄 | 卡片顯示最近一次詢價日期，以及仍在進行的案件 |
| 從商品反查等貨 | 「更多篩選」裡選一個商品，列出所有在等這個商品的客人。手動新增等貨時可以指定商品和聯絡管道 |
| 聯絡管道 | 分開記最初來源和目前管道。「轉 LINE」：確認是同一個人後，手動把 LINE 身分關聯到這位客人，不會自動合併；卡片顯示「Threads → LINE」 |
| 語言、地區、付款方式 | 在「客人資料」表單裡人工填寫。付款方式分「偏好」和「上次實際使用」，不填帳號 |
| 介紹來源、聯絡人類型 | 聯絡人類型可複選：客人、朋友、供應商、抽獎對象 |
| 教學與售後待辦 | 從聊天抓三種：「需要換綁教學」「換綁失敗」「催交付」，掛在對應案件上，也可以手動新增。已交付超過 7 天的歷史案件，預設為已處理，只保留紀錄；重新匯入不會把已處理的待辦再打開 |
| 顯示設定 | 每個特徵都可以「放到首頁、往前、移出首頁、隱藏、重新顯示」，設定存在後台；隱藏只影響畫面，資料保留。預設首頁和規格一致：熟客、高單價成交、等貨，加上商品搜尋 |
| 網站訂單金額 | 改用商品小計扣除退款（規格說的「商品成交額」） |
| 待核款 | 案件上註明「確認入帳與交付請走訂單流程」。是否從待核款直接建立訂單，等老闆決定歷史成交用 A 或 B |
